# 为什么"只学修复动作"的 SFT 会失败

结论（2026-09-30 对照实验后修订）：把 memory 控制器的修复动作切片与**异源批次**数据混入 SFT，
会让 VLA 灾难性退化为近似常量输出、成功率归零；塌缩由**批次错配**携带，与修复动作内容无关——
同源修复段加权不引发塌缩（对照实验见"原因"一节）。同源强化的代价是大范围退化（2× 权重下
68-case 成功率 22→2），剂量效应成立。此前记录的"欠定"解释未获验证，撤回；
已排除项见"已排除的解释"。

## 证据

同样的配置（1 epoch、LoRA r8/alpha16、lr 1e-5、同一个 base checkpoint），只改训练数据：

| 训练数据                  | episode | windows | 切片占比 | clean 场景 |
|---------------------------|---------|---------|----------|------------|
| 63 条 v2 完整轨迹          | 63      | 16,228  | 0%       | **3/3** ✓  |
| v2 完整轨迹 + 121 条切片   | 184     | 21,306  | 25.7%    | **0/3** ✗  |
| 121 条切片（v1 切片）      | 121     | 5,481   | 100%     | **0/3** ✗  |
| base（未微调）             | —       | —       | —        | **2/2** ✓  |

clean 场景 = 无干扰、默认初始态、文本条件与训练一致。

注：那 68 个扰动 case 是筛选出来的 **base 失败案例**，所以 base ≈ 0/68，v2 微调 = 22/68。
**SFT 模仿本身是有效的**，失效的是"修复动作"这一类模仿目标。

## 失败模式：输出退化成近似常量

从评测时实际记录的动作统计（每个模型 2–4 条 clean episode）：

| 模型     | episode 步数        | 时间标准差 dx | 夹爪 死区/开/关        |
|----------|---------------------|---------------|------------------------|
| base     | 209–222（完成任务） | 0.2249        | 0.0% / 34.1% / 65.9%   |
| v2       | 246–270（完成任务） | 0.1849        | 0.5% / 43.4% / 56.1%   |
| v2+切片  | 520（跑满超时）     | 0.0403        | 100% / 0% / 0%         |
| 只有切片 | 520（跑满超时）     | 0.0284        | 100% / 0% / 0%         |

七个维度同时塌（时间标准差降到 v2 的 1/5–1/6），夹爪全程停在死区，从没发出过一次开合指令。
两个剂量（25.7% 和 100%）塌得几乎一样——这不像剂量效应。

## 原因（2026-09-30 受控对照实验）

对照实验：从 63 条 v2 完整轨迹内部抽取各自最长的控制器修复段（死区游程指纹定位，
62 条 × 64 步，与 `build_repair_slices.py` 同规格，逐字节与源一致），以片段文件与完整轨迹
拼接训练（`DROP_TAIL=1`、1 epoch = 2,358 iter、其余配置同原混合 run）。与原混合行相比
唯一实质差别是片段来源（同源 vs 异源批次）。产物：`training/tta_sft_own_repair_segments_v1/`、
`memory_system/tta/tools/build_own_repair_segments.py`、`training/tta_sft_ownseg_e1_merged.pt`、
`scripts/experiments/ownseg_probe/`、`scripts/experiments/tta_sft_ownseg_68/`。

结果：同源混合**不塌缩**——clean 配对评测动作 std 0.17–0.21（塌缩模型 0.04）、夹爪 98–100%
果断开合、完成抓+放后卡在关抽屉步（0/2）；68 个扰动 case 完成 56 个时仅成功 2 个
（v2 同口径 22/68，二项检验排除波动；余 12 个即使全成也只 14/68）。三个命题的回答：

1. **"最好不要强化修复片段"——有实证支撑（限本配方）**。剂量轴：1×（v2 自然内嵌，
   修复窗口占 18%）→ 22/68 有效；2×（同源复制，占 ~31%）→ ~2/68 大范围退化（粗容差
   技能保留、精细收尾/修正能力受损，与 clean 评测分层失效一致）；异源切片 25.7% →
   灾难性塌缩。强化修复段不是中性操作。
2. **"不是代码错误"——已验证**。切片与片段逐字节与源一致、v2 轨迹尾部完整（19/19 条
   抽屉轨迹以关门结尾，"结尾被截断"排除）、标签无错位、归一化统计一致。伤害来自训练
   动态，非数据管线缺陷。
3. **"是训练特性"——限本配方成立**。指 LoRA r8 + 1 epoch + EDM 此配方下的行为；
   提高容量或换目标后是否同样，未测。

仍未解决：异源批次为何把函数拉向标签均值——机制草图为"流形外状态的大梯度经低秩共享
方向全局外溢"，与全部实测签名相容但未经逐步验证；同源 2× 与 v2 之间尚有数据集类
（丢尾窗 vs padding，约 2.5% 窗口差）与迭代数（2358 vs 2030）两处小差异，在 22→2 的
效应量下不构成主因，但非严格单变量。

## 已排除的解释（均有实测）

- **归一化尺度错配**：训练与评测用的 stats 文件 `cmp` 逐字节相同
- **merge 出错**：merged 与 base 的差异 tensor 数量/位置，和已知可用的 v2 版完全相同
- **数据配对错位**：121/121 切片与源文件 `[t*, t*+L)` 逐字节一致；源文件 `frame_indices`
  也验过（`[0]==0`、前缀连续 `0..t*-1`、接缝从 10 开始）
- **夹爪单维塌缩**：实测是七维整体塌，不是夹爪一维
- **训练不足**：步数比 v2 少，但训练不足只会更接近 base，不会更坏

## 未验证 / 可能的出路

- 更小的切片占比（< 25%）没测过（同源 16% 不塌但已退化，异源低剂量未测）
- 改用对比目标（DPO：`PreferenceDataset` + `build_manifest.py`）——只要求区分
  chosen/rejected，不要求复现控制器的动作
- 改数据采集，让修复动作成为观测的函数，而不是控制器内部计划的产物
- 换配方验证"训练特性"的边界：提高 LoRA rank / 全量微调 / 换目标函数
