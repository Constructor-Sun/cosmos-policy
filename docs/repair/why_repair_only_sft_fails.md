# 为什么"只学修复动作"的 SFT 会失败

结论：把 memory 控制器的修复动作当作模仿目标，会让 VLA 退化成近似常量的输出，任务成功率归零。
加进完整轨迹做锚也救不回来。原因是这个映射本身欠定——不是剂量、归一化或数据配对的问题。

## 证据

同样的配置（1 epoch、LoRA r8/alpha16、lr 1e-5、同一个 base checkpoint），只改训练数据：

| 训练数据                  | episode | windows | 切片占比 | clean 场景 |
|---------------------------|---------|---------|----------|------------|
| 63 条 v2 完整轨迹          | 63      | 16,228  | 0%       | **3/3** ✓  |
| v2 完整轨迹 + 121 条切片   | 184     | 21,306  | 25.7%    | **0/3** ✗  |
| 121 条切片（v1 切片）      | 121     | 5,481   | 100%     | **0/3** ✗  |
| base（未微调）             | —       | —       | —        | **2/2** ✓  |

clean 场景 = 无干扰、默认初始态、文本条件与训练一致。

注：那 68 个扰动 case 是筛选出来的 **base 失败案例**，所以 base ≈ 0/68，v2 微调 = 22/68。
**SFT 模仿本身是有效的**，失效的是"修复动作"这一类模仿目标。

## 失败模式：输出退化成近似常量

从评测时实际记录的动作统计（每个模型 2–4 条 clean episode）：

| 模型     | episode 步数        | 时间标准差 dx | 夹爪 死区/开/关        |
|----------|---------------------|---------------|------------------------|
| base     | 209–222（完成任务） | 0.2249        | 0.0% / 34.1% / 65.9%   |
| v2       | 246–270（完成任务） | 0.1849        | 0.5% / 43.4% / 56.1%   |
| v2+切片  | 520（跑满超时）     | 0.0403        | 100% / 0% / 0%         |
| 只有切片 | 520（跑满超时）     | 0.0284        | 100% / 0% / 0%         |

七个维度同时塌（时间标准差降到 v2 的 1/5–1/6），夹爪全程停在死区，从没发出过一次开合指令。
两个剂量（25.7% 和 100%）塌得几乎一样——这不像剂量效应。

## 为什么：修复动作对观测是欠定的

VLA 自己的动作是它对当前观测的反应，`观测 → 动作` 良定义，所以模仿有效（v2 = 22/68）。

修复动作不是。它由 memory 系统的内部状态决定——检索到哪条 demo、规划出什么轨迹、
目标位姿是什么——这些都不在当前这一帧观测里。让 VLA 只看单帧去复现，
映射本身没有唯一解，网络只能退化成常数来最小化损失。

这解释了加锚为什么无效：不是修复信号被稀释，是这个映射**根本不可学**，掺多少都一样。

## 已排除的解释（均有实测）

- **归一化尺度错配**：训练与评测用的 stats 文件 `cmp` 逐字节相同
- **merge 出错**：merged 与 base 的差异 tensor 数量/位置，和已知可用的 v2 版完全相同
- **数据配对错位**：121/121 切片与源文件 `[t*, t*+L)` 逐字节一致；源文件 `frame_indices`
  也验过（`[0]==0`、前缀连续 `0..t*-1`、接缝从 10 开始）
- **夹爪单维塌缩**：实测是七维整体塌，不是夹爪一维
- **训练不足**：步数比 v2 少，但训练不足只会更接近 base，不会更坏

## 未验证 / 可能的出路

- 更小的切片占比（< 25%）没测过；但按上面的分析，小到不破坏时信号也基本没了
- 改用对比目标（DPO：`PreferenceDataset` + `build_manifest.py`）——只要求区分
  chosen/rejected，不要求复现控制器的动作，绕开欠定问题
- 改数据采集，让修复动作成为观测的函数，而不是控制器内部计划的产物
