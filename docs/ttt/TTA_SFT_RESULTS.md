# TTA SFT 训练结果与失败分析

前提：阅读本文前先看 `TTA_LoRAFix.md`——本文所有结果均基于修复 LoRA 死初始化之后的重训，修复前的一切评测数字作废。日期：2026-09-13。

## 1. 实验设置

- 数据：61 条修复成功轨迹（7 个 LIBERO-10 任务、robotinit 变体；每条 = 扰动初始态前缀回放 + 闭环控制器修复 + base 策略续行至成功）。
- 训练：LoRA SFT（rank 8 / alpha 16）、标准 AdamW、2030 iters、6 卡、启动器含 LoRA 重初始化修复（`tests/tta/train_tta_sft_fixed.py`）。
- 评测：68 个 base 失败 case（修复能力）+ 132 个 base 通过 case（部署回归）。

## 2. 结果

| 配置 | 68 失败 case（修复能力） | 132 通过 case（部署回归） |
|---|---|---|
| base policy | 0/68（按构造） | ~132/132（按构造） |
| 修复前 SFT（LoRA 死锁，作废） | 10/68 | 从未跑成 |
| **修复后 SFT（本次）** | **22/68 = 32%** | **125/132 = 94.7%** |
| memory 修复机制（上限参照） | 61/68 = 90% | 不适用（非裸部署） |

净效果：全部 200 case 上净增 +15（+22 恢复 −7 回退）。

| 任务 | 训练数据 | 68 case 成功率 | 任务性质 |
|---|---|---|---|
| KSCENE6 微波炉关门 | 3 | **100%** (4/4) | 容差大 |
| LRSCENE6 盘+布丁 | 4 | 75% (3/4) | 容差中 |

| LRSCENE5 左右盘 | 19 | 5% (1/20) | 精确辨位 |

## 3. SFT 的失败之处

1. **数据量与成功率零相关**：LRSCENE5 拿着第二多的数据（19 条）只有 5%，KSCENE6 用 3 条就 100%。堆数据解决不了失败任务，瓶颈不在数据量。
2. **分界线是容差**：成功 ≥50% 的任务全是"放进区域/推拉/上台面"类（终点是区域或开关，轨迹偏差仍可成功）；失败的任务全是"空间关系精放/辨别"类——开环 BC 的误差累积在容差小的任务上必然越界。
3. **闭环→开环克隆差距**：裸 SFT 32% vs memory 修复 90%。58 个点的差距 = 用开环 BC 模仿闭环控制器动作的结构性损失（无反馈执行时误差复利发散）。
4. **阶段覆盖缺口**：每条训练轨迹只含一个相位的一次修复（绝大多数是 Pick 相位）；Place、关门等其他相位的修复从未进入监督信号。SFT 只学会了数据里出现过的那次修复，没有学过"每个阶段的修复"。
5. **部署代价**：132 个 base 会做的任务回退 5.3%（分布漂移）。LRSCENE2 在失败 case 上从（作废版的）6/12 掉到 1/12，是同一漂移的信号。

## 4. 下一步：DPO 通道（建议尝试）

**为什么值得**（三个结构性增量）：

1. 不要求逐帧克隆闭环动作，只要求去噪方向偏好 chosen、排斥 rejected——直接攻击第 3 条的 58 个点差距；
2. rejected 信号**显式惩罚辨别型失败**（"别接近错的那一侧"）——对准 LRSCENE5/LRSCENE2 这类对比型失败，而 SFT 的纯正样本信号对此很弱；
3. reference = base 本身，为无偏好信号的区域提供锚定——132 回退有望显著缩小。

**不会解决什么**：阶段覆盖缺口（第 4 条）。DPO 的训练对来自同一批 68 个 case、同一批失败相位，数据覆盖面与 SFT 完全相同。该缺口要靠按阶段 deliberate 造修复数据，或部署时保留 memory 修复兜底。

**就绪度**：代码已验证（`memory_system/tta/` 的 TTADPOModel，22/22 CPU 测试 + 真模型 GPU 验证 PASS）；缺口是 rejected 轨迹无图像（用 `replay_rejected.py` 确定性重放补图，无需 policy 推理）+ manifest 重建（`build_manifest.py`）+ eval 侧接 `attach_adapter`。

**判决矩阵（跑前注册）**：

| 结果 | 结论 | 下一步 |
|---|---|---|
| DPO 68 成功率 > SFT 的 32%（如 ≥45%） | 偏好通道胜出 | 加大 DPO（更多对/更多步），SFT 降级 |
| DPO ≈ SFT（30% 上下） | 瓶颈在数据覆盖/执行精度 | 主攻按阶段修复数据 |
| DPO < SFT | 小数据下偏好信号不稳 | 混合部署（SFT + memory 按需兜底）为 pragmatic 终点 |
