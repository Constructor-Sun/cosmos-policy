# Traj 后修正：两个讨论

只保留两个问题的结论与做法：**1. 如何平滑轨迹（速度意义上）；2. 如何做到稳定夹持物体**。

## 讨论 1：如何平滑轨迹

**平滑的定义**：速度不突变。轨迹是位置序列 p₀, p₁, …，每步速度 v_i = p_{i+1} − p_i（三维向量，含大小和方向）；平滑 = 相邻两步的速度向量差 ‖v_{i+1} − v_i‖ 全程有界，上界取原始轨迹自身的抖动水平（不追求绝对恒速）。

**实测结论：物理轨迹本来就是平滑的。** 全库 1700 条 success：单步位移 p50 = 7.7mm（max 23.4mm），相邻步速度差全程 ≤5.5mm。不平滑只存在于指令信号里（policy 每个 chunk 边界的 delta 抖动），而伺服是低通滤波器，指令抖动到机器人上已经被滤掉了。

**因此平滑的做法是"不处理"**：物理层无可修。曾尝试把指令序列在停顿出口等接缝处重排成 C1 连续（五次曲线重布），真实回放实测切入偏差 16–29cm——伺服存在显著跟踪滞后（指令 p50 0.466 单位、实际步进仅 5.3mm），命令重排被滞后积分放大。平滑指令与"回放精确落在诊断状态"二选一，保真优先，该设计否决。

**实际交付：停顿跳过**（`memory_system/tta/replay_retime.py`，52 行）。删掉近零指令（<0.3mm/步、夹爪静止、不跨夹爪事件 ±3 帧；长停顿每 10 帧留 1 锚点），其余指令原样。跳过近零指令是执行精确的：物理响应不变。实测：无跳过 case 切入偏差 0.0mm（逐位一致），有跳过 case ≤28mm 且由闭环对齐吸收；速度抖动与原始序列完全相等。单测 `tests/test_replay_retime.py` 5/5。

**检测口径**：重放/修改后的物理轨迹（状态记录，非指令）的 max‖v_{i+1} − v_i‖ ≤ 原始序列自身抖动水平，即"没有新增突变"。

## 讨论 2：如何做到稳定夹持

**先定义"稳"**：携带段（闭爪后→开爪前）满足两条——① 接触不断；② 物体不从指间逃逸（中心到两指尖连线的距离不增长）。

**先说不是"不稳"的东西（v1 教训）**：物体绕指尖摆动 180°、绕夹爪轴自转 110°——实测这些 case 接触保持 True、任务成功。摆动和自转是捏取抓取的正常物理（像两指夹一串钥匙，钥匙晃但不掉），v1 的 wobble 标量把摆动/自转/真打滑混在一起判，作废。

**怎么判稳（简化为单一判据）**：携带段逐帧 `_check_grasp` 接触连续性。断了 = 不稳；没断 = 稳。逃逸度量（中心到指尖连线距离的增长）本轮暂缓——成功库里没有掉落正样本，阈值定不了，等真出现掉落案例再启用。被夹物体身份由接触决定（锚点帧对所有候选物体测接触），不由清单匹配决定（双物体任务曾因此错配）。

**怎么做到稳（实现途径）**：
1. **对齐到被验证过的闭爪位姿**：memory 里每个 Pick 相位的闭爪位姿，只有携带段接触连续性通过的 demo 才可作为对齐目标——TTA 修复把机器人带到的是"被验证能夹稳的位姿"，不是任意位姿。
2. **新闭爪必须过检**：修复轨迹（对齐后新闭爪，无历史背书）回收进 memory 前，携带段接触连续性是唯一关卡；不过关 → 不回收，进重生成清单。
3. **不稳时的动作**：不修补不稳的抓取——重新对齐到已验证位姿重夹一次，仍不稳则该位姿进重生成清单。

依赖说明：接触查询需要模拟器物理内核（`set_state + forward`，CPU，无渲染），且要求轨迹文件携带逐帧 `states`（memory 源 demo 均满足；eval 型 h5 无 states，需重放）。真机上此信号需替换为力/触觉方案，判据框架不变。
